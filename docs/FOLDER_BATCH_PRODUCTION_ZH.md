# Windows 脚本目录一键批量制作

双击项目根目录的 `一键批量产出.cmd`，程序会递归扫描 `D:\脚本` 中的 Word 文档，并把每份 Word 所在文件夹中的 PNG/JPG/JPEG/WebP 图片当作该产品组的共享参考图。它会先显示文件 SHA-256、图片 SHA-256、分组与服务能力预检；确认后逐个导入 Word、按图片哈希同步到产品图库、启动自动视频制作并等待结果。

默认质量配置是 `resolution=4k`、`mode=fast`、`processing=seedvr2`、`aspect_ratio=16:9`。Fast 是否实际使用 4-step 由所连接应用的模型路由决定；应用必须明确报告可用的本地 SMD4 Fast 工作流，SeedVR2 也必须通过相同分辨率和画幅的能力预检。任何一项未验证，程序都不会悄悄退回其他质量路径。云端计费和付费回退固定为关闭。

## 连接应用

默认 API 是 `http://127.0.0.1:8765`。要连接另一台已运行本项目后端的主机，可设置环境变量 `VIDEO_FACTORY_API_URL`，或在 `.local-runtime\folder-production-api.txt` 中写入应用 API 基址（例如 `http://HOST:8765`）。该文件只保存地址，不保存 API Key。远程服务需由使用者按其部署方式建立可访问且受保护的连接；这个启动器不会自行开放 Vast 端口或更改防火墙。

开始批量制作前，确保 API 返回 `/api/health` 正常、4K/16:9 SeedVR2 能力为已验证，并且本地模型档案指向本地 H3 Fast/4-step 路由。未满足时，预检会显示阻断原因。

## 文件夹规则

- 一个产品文件夹可放多份 Word 和多张产品图片；该文件夹内每份 Word 都绑定同一组有效图片。
- 多级目录各自构成产品组；同一图片只在产品图库中按 SHA-256 上传一次。
- 文档若明确写有 Owala FreeSip，程序可以使用该明确产品名；其他情况以相对文件夹路径作为产品记录名称，不猜测品牌或规格。
- 无效/损坏的单份 Word 或图片会单独隔离并报告，不影响其他候选。一个目录超过 8 张图时需先按当前产品选择结构人工精简，程序不会静默丢图。
- Word 文件保持原样；仅上传原始 DOCX 字节和同目录图片。

## 断点续跑与重复保护

`data\folder_production_state.json` 保存源文件哈希、图片哈希、质量参数、去敏 API 主机和项目/run ID。相同输入已提交、运行中、完成或提交结果未知时，会被跳过，避免重复派单。网络写入超时会标记为结果未知；应先在应用中核对项目状态，程序不会自动重试这类写操作。只有明确失败于预检、尚未创建项目的条目，才可用命令行 `--retry-failed` 重新验证。

双击启动器后，第一次预检是只读操作；只有明确输入 `START ALL` 才会开始批量导入和生成。日志和防重复台账保存在项目本地 `data/` 下，不会提交到 Git。

命令行预检：

```powershell
D:\人物一致性\.venv\Scripts\python.exe D:\人物一致性\scripts\one_click_folder_production.py --root D:\脚本 --all --dry-run --limit 500
```
