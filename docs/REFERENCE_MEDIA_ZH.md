# 原生 H3 参考图片与视频

MiniMax H3 Ref2VA 的输入由三类独立资料组成：脚本决定内容，图片决定人物或商品的视觉身份，视频提供动作、物理交互、运镜与画面风格参考。每一项都是可选的；没有参考视频时，纯脚本和图片参考路径保持可用。

## 在项目中配置

1. 导入或创建脚本后，在项目工作台上传人物/产品图片，或从图库选择已有素材。
2. 打开“参考视频（可选）”，上传视频或从当前项目的视频素材中选择。
3. 查看缩略图、时长、尺寸和帧率，选择用途：**动作模仿、运镜模仿、画面风格或综合参考**。默认是综合参考。
4. 指定片段起止时间，保存项目默认值；单个分镜可以覆盖项目默认值或清空自己的绑定。
5. 选择 Fast、标准或高质量并开始制作。任务快照会保存素材 SHA256、用途、片段、实际提示词、工作流与 ComfyUI prompt ID。

一个项目只有一条默认参考视频时，页面可以将其作为所有分镜的初始选择；每个镜头仍可独立替换、修改片段或移除，且不会继承其他项目的素材。

## 图片与视频怎样进入模型

```text
镜头脚本 + 已明确绑定的产品/人物图片 + 可选参考视频
  → 文件类型、SHA256、解码与片段校验
  → 图片按固定顺序上传；视频保留原件并转为 24 FPS 模型副本
  → ComfyUI LoadVideo / GetVideoComponents
  → MiniMaxH3ReferenceToVideo 的 Picture N 与 Video N 原生输入
  → H3 生成 → 技术检查 → 已验证的 AI 超分 → 成片
```

这条路径不会先让独立语言模型分析或改写图片、视频或剧本文字。脚本原文和由用途生成的简短确定性参考说明分别保存；实际提交提示词可在任务的复现快照中查看。

图片与视频编号相互独立：`Picture 1`、`Picture 2` 等用于视觉身份，`Video 1`、`Video 2` 等用于参考动作/镜头。参考视频中出现的商品不会覆盖已绑定图片的商品身份。若两者不同，提示词会明确要求保留图片中的真实商品结构，只借鉴视频指定的动作、运镜或风格。

## 输入验证与限制

上传时会检查容器格式、实际编码、分辨率、帧率、时长、音频流、完整解码和 SHA256；不只根据文件扩展名判断类型。模型副本会处理旋转元数据、保持原始画面比例，并在转换后再次解码。原文件始终保留。

当前前端会显示并验证以下原生输入预算；实际节点 schema、模型版本和显存不足时会进一步阻止派发，而不会静默丢弃输入：

- 最多 9 张图片；
- 最多 3 段视频；
- 每段视频为 2–15 秒，视频总时长不超过 15 秒；
- 最多 3 段独立音频；
- 图片、视频与独立音频合计最多 12 个文件。

默认参考视频仅提供视觉条件，不自动复用原音轨。只有用户明确启用参考音频、且当前 H3 节点公开匹配的 `ref_video_audio_N` 插槽时，系统才连接该音频；否则视频音频不参与生成。

## 质量与排错边界

- Fast 使用真实 SMD 4-step LoRA 配方；标准和高质量分别使用原生 20/30 步配置。不能只改步数冒充 Fast。
- 已成功提交不等于输出成功。任务必须取得真实 MP4、通过时长/帧率/画幅/解码检查，并完成所选的 AI 超分，才能进入相应完成状态。
- 图片、视频和脚本的约束会提高一致性，但模型不能保证小字、商标、手部或复杂接触完全正确；请播放审核。
- 当节点没有公开视频加载器、组件输出或 H3 视频参考插槽时，系统应明确拒绝视频参考任务，而不是退化成截图或忽略视频。

排错时保留任务 ID、素材 SHA256、ComfyUI prompt ID 和脱敏错误。不要通过删图库、修改数据库或重复提交未知状态的模型任务来处理失败。
